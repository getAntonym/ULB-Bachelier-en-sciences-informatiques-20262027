# Mémoire primaire

## Rôle et organisation

> [!NOTE]
> **Mémoire de travail**
>
> La mémoire primaire est une mémoire temporaire, utilisée pour le travail de l’ordinateur.
>
> Ordre de grandeur noté en cours : **quelques Go**.

### Structure et adresses

La mémoire est découpée en **cases de taille fixe de 1 octet**. Chaque case possède un numéro : son **adresse mémoire**.
### Lecture et écriture

| Opération | Rôle | Notation |
| :--- | :--- | :--- |
| **Lecture** | Récupérer une donnée à une adresse | `lecture(adresse a)` |
| **Écriture** | Modifier une donnée à une adresse | `écriture(donnée d, adresse a)` |

## Mémoire cache

La mémoire cache conserve une **copie d’une partie des données et des instructions de la mémoire centrale**, pour réduire le temps d’accès du CPU. Les caches sont généralement intégrés au processeur ; leur organisation dépend de l’architecture.

> [!IMPORTANT]
> **Compromis**
>
> La mémoire cache est **plus rapide**, mais **plus petite** que la mémoire centrale.

### Succès et échec de cache

Quand le CPU effectue une lecture :

| Situation | Terme |
| :--- | :--- |
| La donnée est présente dans le cache | **Cache hit** — succès |
| La donnée n’est pas présente dans le cache | **Cache miss** — échec |

### Efficacité du cache

Le cache est utile lorsqu’il contient les informations dont le CPU a besoin. Des mécanismes peuvent anticiper certains accès pour y charger les prochaines données utiles.

### Hiérarchie mémoire

| Élément | Place dans la hiérarchie |
| :--- | :--- |
| **Registres** | Très petites mémoires directement utilisées par le CPU |
| **Cache L1** | Petit et très rapide |
| **Cache L2** | Généralement plus grand et plus lent que L1 |
| **Mémoire centrale** | Plus grande, mais plus lente que les caches |

> [!NOTE]
> Les capacités sont propres au matériel. Les registres et la mémoire centrale ne sont pas des niveaux de cache.

## Ordre des octets dans les mots

Un entier sur **32 bits occupe 4 octets**. Pour le stocker dans une mémoire adressée par octet, il faut choisir quel octet placer à l’adresse la plus basse.

Prenons le mot hexadécimal **0x12345678**, stocké à partir de l’adresse **a** :

| Convention | Adresse a | a + 1 | a + 2 | a + 3 |
| :--- | :---: | :---: | :---: | :---: |
| **Big endian** — gros-boutiste | `12` | `34` | `56` | `78` |
| **Little endian** — petit-boutiste | `78` | `56` | `34` | `12` |

- **Big endian** : l’octet de poids fort est placé à l’adresse la plus basse.
- **Little endian** : l’octet de poids faible est placé à l’adresse la plus basse.

> [!IMPORTANT]
> **Ordre des octets, pas des bits**
>
> On change la position des octets dans le mot, pas l’ordre des bits à l’intérieur de chaque octet. Le processeur i486 utilisé comme exemple dans le syllabus est little endian.

L’ordre des octets doit être connu pour échanger des valeurs multioctets entre machines ou interpréter un fichier. On n’inverse pas automatiquement les octets d’une chaîne ASCII : chaque caractère y occupe un octet distinct.
